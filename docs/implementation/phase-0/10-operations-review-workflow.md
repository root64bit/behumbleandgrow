# 10. Operations Review Workflow Specification

## Overview
This document specifies the internal operations review workflow for submitted candidate applications, document verification, and status transitions within the **BE HUMBLE & GROW** platform.

## Operations Queue & Processing Stages

1. **Submitted Application Ingestion**:
   - Applications submitted by candidates land in the `applications` table with stage `employer_submitted` and status `submitted`.
   - Operations officers view the queue at `/operations/applications`.

2. **Document Verification**:
   - Document reviewers inspect uploaded candidate identity, CV, and certificate records.
   - Privileged reviewers retrieve short-lived signed URLs generated by `storage.service.ts` (30-minute expiry).
   - Review status transitions: `uploaded` → `under_review` → `verified` / `rejected` / `replacement_requested`.

3. **Status Transitions & Audit History**:
   - Every status change (e.g. `submitted` → `shortlisted` or `rejected`) creates an append-only entry in `public.status_history`.
   - Audit logs capture actor ID, role (`operations_admin`, `candidate_reviewer`, etc.), timestamp, and internal notes.
   - Candidates receive real-time or polling status updates in their dashboard without exposing internal reviewer notes.
